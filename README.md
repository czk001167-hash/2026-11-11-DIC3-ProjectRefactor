# 交通配時助手（Traffic Timing Assistant）

## 摘要

### A. Attention Getter (背景與動機)
交通號誌是城市交通效率與安全的關鍵基礎設施，但傳統固定配時多依平均或離峰流量預先設定，難以因應不同方向、時段與突發車流的變化。美國 Maricopa County 的 AI 自適應號誌試辦顯示，透過攝影機即時車流資料動態調整時制後，單一路口在一週評估中使平均車輛延滯降低約 46%、橫向車流延滯降低約 54%，並估計每週可節省 322 小時車輛延滯。 這顯示，若號誌能依即時需求調整，將有機會有效降低等待時間、怠速排放與路口壅塞。

---

### B. But (問題與挑戰)
然而，現有自適應交通控制多著重於大型路網、雲端運算或複雜的深度強化學習，未必適合資源有限、需要快速部署與可檢視決策依據的單一路口情境。此外，傳統自適應控制在飽和或感測受限條件下，可能造成不同方向綠燈時間分配不均，進而影響整體效率與公平性。 因此，如何在單一路口、雙軸直行場景中，建立兼具即時性、可解釋性、邊緣運算能力與安全回退機制的交通配時決策系統，仍是重要的實務缺口。

---

### C. Cure (解決方案)
本專題提出「**交通配時助手**」，作為針對單路口兩軸直行交通的 Domain AI Agent。系統以即時到車量、佇列長度與方向流量差異作為輸入，透過決策樹判斷應採用均衡配時、南北向優先或東西向優先策略，並在 ARM／FPGA 開發板上完成邊緣端推論與號誌控制。當感測資料異常、模型輸出不合理或交通狀態超出設計範圍時，系統將回退至安全規則配時，以維持路口基本運作與可預測性。

- **核心定位**：單路口兩軸直行交通 Domain AI Agent
- **輸入特徵**：即時到車量、佇列長度、方向流量差異
- **決策模型**：決策樹（Decision Tree）
- **策略選擇**：均衡配時、南北向優先、東西向優先
- **硬體平台**：ARM／FPGA 開發板（邊緣運算與號誌控制）
- **安全保障**：具備安全規則回退（Fallback）機制

---

### D. Development (系統架構與開發)
系統架構分為**資料檢查**、**交通狀態分析**、**配時決策**與**安全回退**四個模組：

1. **資料檢查模組**：首先檢查感測資料的完整性與合理性。
2. **交通狀態分析模組**：依據近期到車率、累積佇列與南北、東西向流量差異萃取交通狀態特徵。
3. **配時決策模組**：決策樹模型隨後依據特徵選擇三種配時策略：
   - **均衡配時**：當兩方向需求相近時採用。
   - **優先配時**：當某一方向（南北向或東西向）佇列或到車量明顯較高時採用對應方向優先。
4. **安全回退模組**：系統設定最小綠燈、最長綠燈、清空時間及異常偵測規則；若模型決策違反安全限制，則回退至固定或規則式配時，避免不穩定輸出影響路口運作。

> **設計參考**：此設計參考了以即時佇列與等待時間平衡各方向綠燈分配的研究方向，但將範圍收斂至單一路口與可解釋的決策樹架構。

---

### E. Experiments (實驗與評估)
本研究將以相同交通輸入條件，比較固定配時與交通配時助手政策的表現。

- **模擬情境**：
  - 均衡流量
  - 南北向尖峰
  - 東西向尖峰
  - 突發車流增加
- **評估指標**：
  - 排隊車秒
  - 平均等待時間
  - 方向間延滯差異
  - 車輛通行量
  - 開發板執行一致性
- **文獻參考效益**：
  - 自適應控制相較固定時制通常可降低約 24%–36% 的平均延滯與約 28% 的路口佇列。
  - Maricopa County 案例顯示單一路口平均延滯可降低 46%。
  - *本研究以文獻結果作為效果量級的合理參考，所有結果將於相同輸入、相同評估週期與相同指標下進行比較。*

---

### F. Findings (預期成果與限制)
- **預期成果**：
  - 交付一個可解釋、可在邊緣裝置運行，並具備安全回退機制的交通配時助手展示系統。
  - 依據即時車流狀態，提供均衡、南北優先或東西優先的配時建議，並以決策樹規則說明每次配時選擇的依據。
  - 在模擬環境中驗證降低排隊車秒、平均等待時間，並減少尖峰方向與次要方向之間的延滯差異。
  - 驗證 ARM／FPGA 開發板上的推論結果與控制流程一致性。
- **研究限制與未來工作**：
  - 目前採用簡化 FIFO 佇列模型，尚未進行真實道路長期實測。
  - 實際路口效益、行人與轉向車流、感測誤差及多路口協調等因素，仍需後續以實地資料與更完整交通模擬進一步驗證。
